Question about RAG process
Why can't we simply store PDFs in a normal database
and search them using SQL LIKE '%keyword%'?

Why do we need embeddings and vector search?

Answer
We use embeddings and vector search because
users often ask questions using different words
than those present in the documents.

Traditional keyword searches look for exact words.

Embeddings convert text into vectors representing
meaning.

When a user asks a question, the query is also
converted into an embedding.

Vector similarity search finds the most relevant
document chunks based on meaning rather than exact
word matches.

An additional benefit is that only the relevant
chunks are sent to the LLM, improving performance
and reducing token usage.

*****************## IMPORTANT CONCEPT — Definition vs Execution

One important distinction in LangGraph is that defining a node is different from executing the node.

### Node Definition

A node is a function/Runnable that describes work that LangGraph can execute.

```js
const fallbackNode = async (state) => {

    const response =
        await model.invoke(...);

    return {
        answer: response.content
    };

};
```

At this point, `fallbackNode` has NOT executed yet.

It is only the definition of the work.

We then register it with LangGraph:

```js
.addNode(
    "fallback",
    fallbackNode
)
```

### Node Execution

The node executes only when the graph reaches that node during graph execution.

```text
Graph execution
      ↓
fallback node reached
      ↓
fallbackNode(state)
      ↓
model.invoke()
      ↓
result
      ↓
state update
```

### The mistake to avoid

Do NOT execute the operation first and then pass its result as the node.

❌ Wrong:

```js
const fallbackResponse =
    await model.invoke(...);

.addNode(
    "fallback",
    fallbackResponse
);
```

`fallbackResponse` is already an AIMessage/result.

LangGraph expects a Node function or Runnable.

✅ Correct:

```js
const fallbackResponse = async (state) => {

    const response =
        await model.invoke(...);

    return {
        answer: response.content
    };

};

.addNode(
    "fallback",
    fallbackResponse
);
```

### Connection with Runnable

The same idea applies to LangChain:

```text
Runnable
    = something that CAN be executed

invoke()
    = executes it
```

Similarly:

```text
Node definition
    = work that LangGraph CAN execute

Graph.invoke()
    = executes the workflow
```

### Memory Rule

> Definition ≠ Execution

Or:

> Pass the operation to LangGraph, not the result of executing the operation.

The MCP Client does NOT connect to the AI.

It connects the Host to one or more MCP Servers.
